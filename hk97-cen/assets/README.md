# 자원 형식

모든 자원은 `manifest.json`에 등록되어 있습니다. 항목마다 다음이 들어 있습니다.

- `addr`: 원래 주소
- `slot`: 그 자리의 크기
- `file`: 원본 파일
- `kind`: 형식
- `place`: 옮길 수 있는지 여부
- `new`: 원작에 없던 자원(한국어 대사, 한글 글리프). 원래 주소가 없으면 빈 곳에 배치됩니다.

`tools/pack`이 이 목록대로 파일을 읽어 게임 데이터 이미지를 만듭니다. 새 파일을 추가하는 것이
아니라 기존 파일의 내용을 고치는 것이 기본 사용법입니다.

## 그림 — `graphics/*.png` (`lz_picture`)

- 256×224 **인덱스 컬러(팔레트) PNG**입니다. 32×28 타일을 화면 순서대로 늘어놓은 것이며, 게임이 그대로 BG2에 표시합니다.
- 픽셀 값의 **하위 4비트(0~15)**만 의미가 있습니다. 상위 비트는 미리보기용 팔레트 번호이고 빌드 때 무시됩니다.
- 실제 색은 짝이 되는 `*_palette.json`이 정합니다. 그림 레이어는 팔레트 1~3을 쓰고, 어느 영역이 어느 팔레트인지는 `screens/layout_*.json`이 정합니다.
- RGB(풀컬러) PNG는 받지 않습니다. 편집할 때는 인덱스 모드를 유지하세요(예: GIMP의 "색상표" 모드, Aseprite의 Indexed).
- `gameover`는 원작의 사진 대신 검은 바탕(팔레트 2번)에 흰 글자(1번) "Chin is dead"로 바꿔 두었습니다. 글자는 게임의 8×8 영문 글리프를 2배로 키운 것입니다.
- 원본 이름: `title`, `story1`~`story4`, `gameover`, `stage1`~`stage6`(새 게임마다 다음 배경), `unused_picture`(게임에서 쓰이지 않는 그림)

## 타일 시트 — `graphics/*_tiles.png` (`lz_tiles`)

- 16타일 너비의 인덱스 PNG(4bpp, 픽셀 하위 4비트)입니다.
- `game_tiles.png`: 스프라이트와 HUD 타일(VRAM `$0000`). 스프라이트 프레임 정의는 `sprites/animations.json`에 있습니다.
- `story2_layer_tiles.png` / `story3_layer_tiles.png`: 스토리 2·3쪽의 앞 레이어(BG1). 배치는 `*_layer_map.json`이 정합니다.

## 타일맵 — `*_layer_map.json` (`lz_tilemap`)

- 32줄 × 32칸의 16비트 값(16진수)입니다.
- 비트 구성은 `vhopppcc cccccccc`입니다: 세로/가로 뒤집기, 우선순위, 팔레트, 타일 번호.

## 팔레트 — `*_palette.json` (`lz_palette`)

- `"#RRGGBB"` 목록입니다. SNES 색은 채널당 5비트라서 각 값의 상위 5비트만 쓰입니다.
- 저장된 값은 정확히 왕복되도록 확장해 둔 것입니다.

## 대사 — `text/**/*.txt` (`text`)

```
# 주석
@2,21 The year 1997 has arrived.
```

- 한 줄이 화면의 한 줄입니다. `@x,y`는 8픽셀 타일 단위 위치입니다.
- **영어 파일(`renderer: 8x8`)**: A–Z a–z 0–9 공백 `. , ! ? ' " - / ( )`만 쓸 수 있습니다.
- **한자·가나 파일(`renderer: 16`)**: 글자 하나가 16×16(가로 2칸)이고, 폰트에 있는 글자만 쓸 수 있습니다.
  - 대응표는 `assetfmt/cjk_gen.go`에 있습니다.
  - 공백은 전각 `　`, 숫자와 영문은 전각(`１２Ａａ`)을 씁니다.
  - 폰트에 없는 글자를 쓰면 빌드가 어느 줄의 어떤 글자인지 알려 주고 멈춥니다.
- 대응표에 없는 코드는 `{01A3}`처럼 16진수로 직접 쓸 수 있습니다.
- 16x16 파일에서는 ASCII 공백·숫자·문장부호를 써도 됩니다. 각각 전각 글자(`　`, `１`, `．` …)로 바뀌고, `-`는 `ー`가 됩니다.
- **한국어 파일(`text/ko/`)**: 한글은 `font/hangul.png`의 글리프로 표시됩니다. 새 글자를 쓰면 `go run ./tools/hangul`로 글리프를 추가하세요.
- 원본 대사의 오자(`遇`, `喋`, `巴` 등)는 원본 글리프 그대로입니다.

## 폰트 — `font/font.png` (`font`)

- 16타일 너비, 2bpp(4색) 인덱스 PNG입니다.
- 8×8 영문 글리프: 코드 c는 타일 c입니다.
- 16×16 글리프: 코드 c는 타일 열 `(c%8)*2`, 타일 행 `(c/8)*2`부터 2×2 타일입니다.
- 크기와 위치가 고정이라 글리프를 고칠 수는 있지만 늘릴 수는 없습니다.

## 한글 글리프 — `font/hangul.png` + `font/hangul.txt` (`font`, 새로 추가)

- 원작 폰트 바로 뒤(`$84:8600`)에 이어지는 16x16 글리프 시트입니다. 형식은 `font.png`와 같고(16타일 너비, 한 줄에 글자 8개), 코드는 `$0218`부터 차례로 붙습니다.
- `hangul.txt`가 각 글리프의 글자를 순서대로 적은 목록입니다. 첫 줄 `@0218`이 첫 코드입니다.
- `tools/hangul`이 대사에 쓰인 글자 중 폰트에 없는 것을 Neo둥근모(SIL OFL 1.1, `tools/hangul/neodgm-OFL.txt`)로 그려 덧붙입니다. 이미 있는 글리프는 건드리지 않으므로 손으로 고친 글리프는 유지됩니다.
- 최대 488자(코드 `$03FF`까지)입니다.

## 스프라이트 — `sprites/animations.json` (`sprites`)

- **`animations`**: 애니메이션 번호별 단계 목록입니다(프레임 번호, 표시 시간, dx, dy). 오브젝트가 애니메이션 번호로 지정합니다.
- **`frames`**: 프레임 1~N의 조각 목록입니다.
  - `x`, `y`: 기준점으로부터의 오프셋(부호 있음)
  - `tile`: 타일 번호
  - `attr`: 속성. `0x80` 세로 뒤집기, `0x40` 가로 뒤집기, `0x0E` 팔레트, `0x10` 16×16 크기, `0x01` 타일 9번째 비트
- **`size_table_a/b`**: 원본 엔진이 애니메이션 단계 위치로 읽는 크기 값입니다. 원본 그대로 보존했습니다.
- **`hitboxes`**: 프레임별 충돌 박스입니다(x오프셋, y오프셋, 폭, 높이).
- 이 은행의 포인터는 `tools/pack`이 매번 다시 계산합니다. 프레임이나 조각을 추가해도 됩니다.

## 표 — 그 밖의 `*.json` (`table`)

```json
{"comment": "...", "fields": [["delay","u8"],["kind","u8"]], "rows": [{"delay":70,"kind":0}, ...], "terminator": "FF"}
```

- 필드 형식: `u8 s8 u16 s16`(10진수), `x8 x16`(16진수 문자열)
- `layout: "columns"`이면 메모리에 열 단위(필드별 배열)로 저장됩니다.
- 주요 표:

| 파일 | 내용 |
|---|---|
| `stage/waves.json` | 적 출현 순서(대기 프레임, 종류). 반복되며, 30마리를 잡으면 보스 등장 |
| `stage/spawn_x.json`, `stage/side_enemy_y.json` | 출현 위치 |
| `objects/drops.json` | 적을 잡을 때 떨어지는 것(순서대로 반복) |
| `objects/touch_kind.json`, `objects/shot_kind.json` | 닿았을 때·맞았을 때 처리 |
| `objects/boss_dive.json`, `objects/wobble.json`, `objects/shooter_speed.json`, `objects/explosion_offsets.json` | 움직임 표 |
| `hud/score_digit_*.json` | 점수 숫자(한자 숫자 〇~八) 위치와 타일 |
| `screens/layout_*.json` | 그림을 어느 영역에 어느 팔레트로 보일지 |
| `menu/language_cursor.json` | 언어 선택 커서 위치 |
| `engine/*.json` | 하드웨어 초기값 등 |

- 행 수를 바꿔도 됩니다. 늘어나면 은행 `$80`의 빈 곳으로 자동 이동합니다.
- 다만 코드가 기대하는 개수가 정해진 표도 있습니다(예: 오브젝트 종류 15개). 그런 표의 행 수는 바꾸지 마세요.

## 사운드 — `sound/spc.json` + `sound/spc_XXXX.bin` (`spc`)

- 부팅 때 SPC700으로 올려 보내는 블록들(목적지 주소, 파일)과 실행 시작 주소입니다.
- `spc_0800.bin`은 사운드 드라이버이고, 나머지는 음악·음색 데이터입니다.
- 게임이 부팅할 때 이 블록들을 사운드 CPU에 올리고, `apu/`가 실행해 음악을 냅니다.

## 헤더 — `header.json`, 미사용 — `unused/*.bin`

- 헤더는 카트리지 정보와 인터럽트 벡터입니다.
- `unused/`는 어떤 코드도 읽지 않는 잔여 바이트입니다(호출되지 않는 죽은 코드 21조각, 쓰이지 않는 표 1개). 이미지를 원본과 맞추려고 보관한 것입니다.
