# 홍콩97 (Hong Kong 97) — 소스 + 자원 프로젝트

SNES 게임 *Hong Kong 97*(HappySoft, 1995)을 **소스 코드와 자원 파일**로 분해해,
원본 ROM 없이 PC(Windows/Linux/macOS)용 실행 파일로 다시 빌드하는 프로젝트입니다.

- 게임 코드: 원본 65816 기계어 약 5,700개 명령어를 Go로 **정적 재컴파일**한 소스 (`recomp/`)
- 게임 데이터: 그림은 PNG, 팔레트·타일맵·표는 JSON, 대사는 UTF-8 텍스트로 꺼낸 자원 (`assets/`)
- 빌드: 자원에서 게임 데이터 이미지를 조립(압축 포함)한 뒤 실행 파일에 내장 — **ROM 파일이 필요 없음**
- **게임오버 그림 교체**: 원작의 고어 사진 대신 검은 바탕에 흰 글자 "Chin is dead"만 나옵니다 (`assets/graphics/gameover.png`)
- **한국어 추가**: 원작의 일본어·중국어·영어에 더해 언어 선택 화면에 `한국어`가 있습니다 (아래 "한국어" 참고)

> 게임의 그림·대사·음악 등은 원저작권자의 것입니다. 이 프로젝트와 빌드 결과물은
> 개인 연구·보관용으로만 쓰고 배포하지 마세요.

## 폴더 구조

```
assets/            게임 데이터 전부 (편집 가능)
  manifest.json      모든 자원의 목록, 원래 주소, 슬롯 크기, 파일 경로 — 빌드의 기준
  graphics/          그림(PNG 256x224), 타일 시트(PNG), 팔레트·타일맵(JSON)
  text/              대사·메뉴 (en/ jp/ cn/ ko/ + 크레딧, 언어 선택)
  font/font.png      영문 8x8 / 한자·가나 16x16 글리프
  font/hangul.png    추가한 한글 16x16 글리프 (+ hangul.txt: 글자 목록)
  sprites/           스프라이트 애니메이션·프레임·충돌 박스(JSON)
  stage/ objects/ hud/ menu/ screens/ engine/   게임 규칙 표(JSON)
  sound/             SPC700 사운드 프로그램(바이너리 블록)
  unused/            어디서도 쓰이지 않는 잔여 바이트(죽은 코드 등)
  header.json        카트리지 헤더
cmd/hk97/          게임 실행 파일 (romdata.bin을 내장)
recomp/            재컴파일된 게임 코드 (gen.go는 생성 파일) + 런타임 + 확장(korean.go)
hw/  ppu/          SNES 하드웨어 계층 (메모리 맵, DMA, PPU 렌더러)
apu/               사운드: SPC700 사운드 CPU + S-DSP (assets/sound의 프로그램을 실행)
assetfmt/          자원 형식 변환 (LZ 압축/해제, 타일, 텍스트, 표, 스프라이트)
tools/pack/        assets/ → romdata.bin (+ 자원 주소표)
tools/shot/        게임을 창 없이 돌려 원하는 프레임을 PNG로 저장
tools/hangul/      한국어 대사에 필요한 한글 글리프를 폰트에 추가 (Neo둥근모 글꼴 사용)
docs/              ROM 지도, 디컴파일 의사코드, 형식 설명
--- 아래는 원본 ROM이 있을 때만 쓰는 개발 도구 ---
tools/extract/     ROM → assets/ (최초 1회 실행된 추출기)
tools/recompile/   ROM → recomp/gen.go (재컴파일러, 디스어셈블리, 실행 커버리지)
tools/romap/       ROM 바이트 용도 조사 (코드/데이터/DMA)
oracle/ cmd/oracle/ cmd/compare/   원본을 그대로 돌리는 검증용 실행기와 프레임 비교기
```

## 빌드

Go 1.22 이상이 필요합니다.

**Windows** — `build.bat` 실행, 또는:
```
go mod tidy
go generate ./cmd/hk97
go build -ldflags "-H=windowsgui" -o HongKong97.exe ./cmd/hk97
```

**Linux/macOS** — `./build.sh` (Linux는 X11/OpenGL 개발 패키지 필요:
`libx11-dev libxrandr-dev libxcursor-dev libxinerama-dev libxi-dev libxxf86vm-dev libgl1-mesa-dev libasound2-plugins libasound2-dev`)

`go generate`가 `tools/pack`을 실행해 `assets/`로부터 `cmd/hk97/romdata.bin`과
`cmd/hk97/romdatasyms.json`을 만듭니다. 자원을 고친 뒤에는 이 단계부터 다시 하면 됩니다.

## 자원 고치기

1. `assets/` 안의 파일을 고칩니다. 형식은 `assets/README.md` 참고.
2. `go generate ./cmd/hk97` → 다시 빌드.
3. 빠른 확인: `go run ./tools/shot -in "130:0400,138:0,150:0400,158:0,170:0080,178:0" -at 600,900 -wav shots/sound.wav`
   (입력 스크립트 `프레임:버튼마스크`, 지정한 프레임을 `shots/`에 PNG로, 소리를 WAV로 저장.
   `-spc -2`를 주면 소리 상태를 `.spc` 파일로도 저장해 다른 SPC 플레이어로 들어 볼 수 있습니다)

자원이 커져서 원래 자리에 안 들어가면 `tools/pack`이 빈 공간으로 옮기고, 코드가
그 주소를 쓰도록 주소표를 갱신합니다(코드 안의 자원 참조 148곳이 이름으로 연결되어 있음).
대사·표는 은행 `$80` 안에서, 압축 그래픽은 어디로든 옮겨집니다. 헤더·폰트·스프라이트 은행·
사운드는 위치가 고정입니다.

## 한국어

언어 선택 화면의 네 번째 줄 `한국어`를 고르면(아래 방향키 3번 → 결정) 안내문 3쪽과 스토리 4쪽이
한국어로 나옵니다. 크레딧은 원작에서도 언어와 상관없이 같은 화면이라 그대로입니다.

- **대사**: `assets/text/ko/*.txt`. 16x16 글자라 한 줄에 15칸(x=2부터)이고 스토리는 3줄까지입니다.
  띄어쓰기와 문장부호·숫자도 한 칸씩 차지합니다. 한국어 파일에는 보통 공백·`.`·`,`·숫자를 써도
  되고(전각 글자로 바뀜), 원작 폰트의 기호(`・`, `〒` 등)와 한자도 그대로 쓸 수 있습니다.
- **글리프**: 원작 폰트에는 한글이 없어서, 쓰인 글자(현재 157자 + 마침표·쉼표)만
  Neo둥근모(16x16 도트 글꼴, SIL OFL 1.1)로 그려 폰트 바로 뒤(`$84:8600`, 코드 `$0218`부터)에
  붙였습니다. 원래 그 자리에 있던 그래픽 3개는 `tools/pack`이 빈 곳으로 옮깁니다.
  렌더러가 닿는 범위 때문에 한글 글리프는 최대 488자까지 넣을 수 있습니다.
- **대사를 고쳐 새 글자가 생기면**: `go run ./tools/hangul`로 글리프를 추가한 뒤 다시 빌드합니다
  (`-rebuild`를 주면 안 쓰는 글자를 지우고 다시 그립니다). 빠뜨리면 빌드가 어느 줄의 어떤 글자가
  없는지 알려 줍니다.
- **코드**: 원작은 언어 번호(`$1252`: 0=일본어, 1=중국어, 2=영어)로 점프 테이블 7곳에서 대사를
  고릅니다. 재컴파일러가 표에 없는 번호를 `recomp/ext.go`의 확장으로 넘기게 했고,
  `recomp/korean.go`가 번호 3에 대해 일본어 항목과 같은 동작(16x16 렌더러로 출력)을 한국어 대사로
  수행합니다. 메뉴 커서는 원래 표 데이터로 동작하므로 `assets/menu/language_cursor.json`에 줄을
  하나 더했습니다.
- **검증**: 한국어 경로는 모든 화면을 캡처해 확인했습니다. 일본어·중국어·영어는 메뉴의 한국어 줄만
  뺀 빌드(폰트 확장·자원 이동·코드 확장은 그대로)로 원본과 비교해 영어 9,000 / 중국어 12,000 /
  일본어 30,000프레임 동안 게임 RAM이 일치했습니다. (메뉴 줄을 넣으면 원작 렌더러가 줄마다
  1프레임을 기다리므로 이후 진행이 정확히 1프레임 늦어집니다. 게임 동작은 같습니다.)

## 어떻게 만들었고 어떻게 검증했나

1. ROM을 분석해 65816 코드를 디스어셈블하고(`tools/recompile/listing.asm`),
   검증용 실행기(`oracle/`, 65816 인터프리터 + PPU)로 원본을 실제로 돌려 실행 커버리지와
   ROM 바이트별 용도(코드/데이터/DMA, 읽은 명령어)를 기록했습니다.
2. 재컴파일러가 명령어마다 Go 코드를 생성합니다. 원본처럼 WRAM에 스택을 두므로 스택 조작
   트릭(`PEA`+`JML [$0000]` 등)도 그대로 동작하고, 점프 테이블은 `switch`로 구워 넣었습니다.
3. 데이터는 형식별로 해독해 자원 파일로 꺼냈습니다. 압축 그래픽 33블록은 원본의 LZ 형식을
   해독해 PNG/JSON으로 풀고, 빌드 때 새로 작성한 압축기로 다시 압축합니다(모두 원본보다
   작거나 같은 크기). 대사의 한자·가나 351자는 폰트 글리프를 직접 읽어 유니코드에 대응시켰습니다.
4. 검증:
   - `tools/pack -verify 원본.sfc`: 원작 자원 하나하나를 원본 ROM과 비교(압축 블록은 풀어서).
     한국어를 넣기 전에는 데이터 바이트 279,019개가 모두 일치했고, 지금은 한국어 때문에 고친
     2개(`text_language_select`, `language_cursor`) 외에 모두 일치합니다.
   - `cmd/compare`: 원본 ROM을 돌리는 검증용 실행기와 이 프로젝트의 빌드를 나란히 돌려 매
     논리 프레임마다 RAM을 비교. 영어 9,000프레임, 중국어 12,000프레임, 일본어 30,000프레임
     (사망·재시작 반복으로 스테이지 배경 6종 전부 포함) 동안 게임 RAM 일치.
     차이는 압축기 임시 변수(DP `$00-$0F`, `$29-$2D`)뿐이며, 이는 압축 스트림이 달라졌기 때문입니다.

## 사운드

게임은 부팅할 때 사운드 프로그램(`assets/sound/`)을 사운드 CPU로 올리고 재생 명령을 한 번
보냅니다. 이후 음악은 사운드 CPU가 스스로 반복 재생합니다(이 게임에는 효과음 명령이 없습니다).
`apu/`가 SPC700 CPU(256개 명령, 사이클 단위), 타이머, S-DSP(BRR 디코딩, 가우스 보간, ADSR/GAIN,
노이즈, 피치 변조, 8탭 FIR 에코)를 구현합니다. 업로드는 부트 ROM 대신 같은 프로토콜을 처리하는
코드로 받습니다.

검증: 같은 시점의 사운드 상태를 SPC 파일로 저장해 libgme(검증된 SPC 재생 라이브러리)로 재생한
결과와 비교해 2초 구간마다 상관계수 0.99 이상. 실제 출력 장치로 나간 소리를 녹음해 비교해도
(Linux 빌드, Wine에서 Windows 빌드) 상관계수 1.0000.

## 알려진 점
- `recomp/gen.go`는 기계 생성 코드라 읽기 어렵습니다. 사람이 읽을 수 있게 정리한 핵심 로직은
  `docs/decompiled/`의 의사코드를 참고하세요.
- 원본 게임의 버그(점수 5번째 자리가 오르지 않음 등)도 그대로 재현됩니다.
